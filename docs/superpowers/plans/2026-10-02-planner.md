# Planner: meals + workouts, grocery-ready (draft for review)

Status: draft. Opus plans, Sonnet implements, and the user tests.

## Goal

A **Planner** screen where the user plans the coming days: what to eat and what workout to do. Meal plans carry **structured ingredients**, so a grocery list can be built now and handed to a quick-commerce app (Swiggy Instamart, FirstClub, …) later.

## What exists today (reuse)

- **Planned meals:** per-day placeholders on the Food step (`day.steps[food].planned`), filled from AI suggestions or "Plan a meal". A photo completes them.
- **AI suggestions:** `suggestMeals` returns tomorrow's meals for the eating schedule.

## Proposed

### 1. Planner tab (5th tab, or replace Calendar's spot; see Q1)

- **Week strip:** Mon–Sun. Tapping a day shows **Meals** (the schedule's slots) and **Workout**.
- **Each slot** is a planned item (dish + kcal + macros), plus "Plan" / "Suggest" / "Copy from last week".
- **Status follows the existing rules:** a planned meal stays "Planned" until a photo logs it; a planned workout stays "Planned" until a workout session is logged for that day.

### 2. Workout planning

- `day.steps[workout].plannedWorkouts = [{ id, type, minutes, intensity, note }]`, the same placeholder pattern as meals.
- "Suggest week": Gemini proposes a weekly split from the profile (aim, weight, activity) and last week's logged sessions. Example: walk 30 on Mon/Wed/Fri, gym 45 on Tue/Thu, yoga on Sat, rest on Sun.
- Optional: the Workout step's daily target can follow the plan (see Q3).

### 3. Ingredients and a grocery list (integration-ready)

- **Each planned meal** carries `ingredients: [{ name, qty, unit, category }]`. The category is one of produce, dairy, protein, grains, pantry or other. The AI fills this in; manual meals can add it by hand.
- **The suggestion prompt** asks for ingredients, with quantities for the given number of servings.
- **Grocery list screen:**
  - pick a date range (default: the next 7 days);
  - ingredients are summed by name and unit and grouped by category;
  - each item has a "have it" tick.
- **Today's output:**
  - **Share list** uses the Web Share API, falling back to copy, as plain text for WhatsApp/notes.
  - **Per-item "Search on …" links** open the app's search page. This needs the user to confirm which apps (see Q4).
- **Future integration seam:** `js/grocery.js` builds a provider-neutral `GroceryOrder { items[] }`. A later adapter maps it to a partner API or MCP if Swiggy or FirstClub expose one. As far as we know, no public consumer ordering API exists today, so phase 1 stays share/search only.

### 4. Data and files

- **New files:**
  - `js/grocery.js` (pure: aggregate, group, toText);
  - `js/ui/planner.js` (screen);
  - tests.
- **Changed:** `js/mealPlan.js` (ingredients in schema/parse), `js/gemini.js` (suggest-week for meals and workouts), `js/ui/today.js` (show planned workouts on the Workout step), `js/app.js` (route + tab), `js/backup.js`, `sw.js`.

## Questions for the user

1. **Tab:** add a 5th "Planner" tab, or put the Planner inside Today, as a "Plan" button at the top?
2. **AI scope:** should "Suggest week" plan 7 days of meals in one call (fewer calls, a bigger answer) or one day at a time?
3. **Workout target:** should a planned workout change that day's Workout target (e.g. 45 min on gym days, 0 on rest days), or keep the fixed 30 min?
4. **Grocery apps:** for now, which "search on" links do you want: Swiggy Instamart, FirstClub, Zepto, Blinkit? Or just a shareable list?
5. **Servings:** cooking for 1, or ask the household size, which multiplies the quantities?
